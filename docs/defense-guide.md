# 星芽故事屋：8—10 分钟展示与答辩准备

这是一份**待本人练习和现场讲解的讲稿草案**，不表示已经由学生录屏或完成现场答辩；Trae独立页面已实际创建并留证。请将真实完成的操作、实际媒体时长和模型调用证据填入；没有完成的部分明确说明待验证。

## 展示前先准备

1. 双击 `启动故事屋.cmd`，打开 `http://127.0.0.1:8766`，保持终端运行。
2. 关闭可能露出密钥、聊天隐私或其他个人信息的窗口。设置中只展示“已配置”状态，不录制密钥粘贴过程。
3. 准备至少一个可以顺利打开的完整绘本。若讲真实模型效果，必须选自己实际调用生成的 live 项目；demo 项目应始终说明是本地模板与程序插画。
4. 提前实际生成并保存音视频、Prompt 报告和两个 Agent 案例。现场可回放真实日志与产物，避免把较长网络等待塞进十分钟；若使用预生成结果，现场说明其来源和生成模式。
5. 检查音频播放、系统音量、字幕、视频与导出路径。有声书至少三种实际音色、总时长不少于 180 秒；视频至少 60 秒。
6. Trae实际页面创建及本人第一周录屏已有记录；本次准备重点是完整应用的现场操作与讲解。

### 0:00—0:45：为什么做这个项目

“我的作品叫星芽故事屋，面向亲子阅读场景。用户输入孩子的名字、年龄、兴趣和主题，就能把一个想法做成可以阅读、听读和导出的绘本。项目选择本机运行和免费优先，目的是先让完整流程可用，再根据用户配置连接真实模型。”

“这里明确区分本地体验和真实 AI 创作。本地体验使用模板与程序插画；真实模式调用实际 API。今天展示的森林和海洋均是实际API案例；森林包含用户要求合作结尾的模型修订。较长的图片、语音和视频已预先生成，现场会打开实际作品、播放与检索，并展示真实日志。”

### 0:45—2:00：从用户输入到故事结构

操作：选择一个主题，展示姓名、年龄、兴趣、故事长度和策略；打开已生成的作品，翻到另一个场景，查看角色档案。

“系统将输入组织为结构化故事，包括角色、场景、对白、情绪、视觉提示词和寓意。同一份结构服务于绘本阅读、图片制作、角色配音和视频字幕，而不是分别生成四份互不关联的内容。”

“这里可以按自然语言修订情节。修改会影响后续媒体，所以需要重新生成相关插画、配音和视频，避免新文字配上旧声音。”

### 2:00—3:10：Prompt 比较讲什么

操作：展示 Zero-shot、Few-shot 和角色扮演策略；打开自己的比较报告，指出一处实际输出差异。

“我比较三种提示方式：直接描述任务、加入示例、以及指定儿童文学作家角色。记录结构是否可解析、角色与场景数量、实际输出文本，再由我按连贯性、适龄性、创意和可配图性评价。”

**如果尚无真实 API 结果，应改说：**“当前这份是本地模板比较，用于展示提示词组织与报告流程，尚不能证明真实模型哪种策略更好。真实比较需要我填入密钥后分别调用并评价。”

不要编造“某策略提升了百分之多少”，除非有自己实际记录、可复核的方法与数据。

### 3:10—4:20：图像与角色一致性

操作：并排或连续展示同一主角的两幕图，指出围巾、背包、颜色、外形等固定特征，并展示角色档案和 visual prompt。

“角色一致性依靠统一角色设定和每幕提示词的固定描述。小狐狸小栗的特征是暖橘色、奶油色脸颊与尾尖、青绿围巾、金色背包。我会检查跨场景是否保持这些特征，而不是仅凭‘生成成功’判断一致性。”

本地程序插画能固定角色几何形象；真实文生图即使重复描述也可能漂移，仍须人工检查和迭代。没有真实生成图时，明确展示的是程序插画，不称作真实文生图结果。

### 4:20—5:35：让声音和文字对得上

操作：播放一段旁白、主角、伙伴实际发声的片段；展示同步文字高亮，再播放字幕视频的短片段。只需片段演示，但要能出示完整文件时长。

“有声书使用真实 TTS，为角色绑定不同音色。每段音频解码后按真实样本长度计时，并保存字词边界。阅读器和字幕使用这条时间轴，所以能同步高亮和翻页。失败时不会生成静音来假装配音成功。”

“视频将插画、真实朗读、中文同步字幕和低音量背景音乐合成。课程有声书的 180 秒与视频的 60 秒是两个门槛，要分别检查。”

填写个人实际证据：音色数【 】，完整音频【 】秒，视频【 】秒，项目目录【 】。没有文件时不填写“已完成”。

### 5:35—6:30：素材检索是否真的有用

操作：用自己准备的三个不同查询检索，展示结果相关性和实际引擎标识。例如森林、太空、海洋各一次，再说明有没有错排。

“文本和音效使用本地文本向量检索；图像在模型就绪时使用 ONNX CLIP 图文相似度。当前引擎状态会显示在页面。CLIP 是英文编码器，中文使用公开的主题词典映射，复杂中文不一定能完整表达。”

若页面显示“标签文本向量降级，非 CLIP”，就按实际状态讲，不把降级结果称为 CLIP 实验。

### 6:30—8:10：为什么要保留人的介入

操作：打开 Agent 工作台，选择作品，展示四项核心工具与真实日志；准备一个故事完成后的暂停点，输入明确修改要求，保存介入并恢复，展示后续变化。较长生成可使用已实际完成案例的日志，但需说明是回放。

“四项核心工具是写作、绘图、配音和视频。工具调用需要满足依赖：先有故事和插画，再配音和合成。真实模式可以由模型在允许工具内选择检索、审查与重试；本地模式采用明确标注的规则计划。”

“我把人类检查放在故事完成之后。比如我要求‘减少紧张感，增加分享的情节’，系统先保存指令，在工具边界修订故事，再继续制作衍生媒体。日志记录了何时暂停、输入了什么、后续执行了哪些工具。”

两个案例需由本人核对：案例 A【主题、干预要求、实际结果】，案例 B【主题、干预要求、实际结果】。仅存在两个书架封面，不等于完成两个完整 Agent 案例。

## 常见答辩问题

**问：这是模型自主 Agent，还是固定工作流？**  
答：两种模式分开标注。demo 使用固定规则规划；live 注入模型规划器，在工具白名单和依赖约束内选择分支。StructuredTool 负责实际调用，程序检查执行顺序。需要用 live 日志证明实际发生了模型规划。

**问：免费优先如何控制？**  
答：后端校验服务地址与模型白名单，不只依赖前端下拉框。账号当前权限和限额仍以平台为准；错误会显式返回，不自动购买或切换付费服务。

**问：为什么可以确定有三个音色？**  
答：看实际已生成的音频证明与试听。证明记录实际使用的 voice、逐段时长与校验值，至少三个音色都必须有对白真正发声；配置中写了三个名字还不算。

**问：怎么保证音频与字幕同步？**  
答：先解码音频，以实际样本时长拼接，结合 TTS 字词边界生成时间轴；不按字符数随意估算整段时长。仍需本人试听和检查边界。

**问：修改故事后为什么要重做媒体？**  
答：对白、场景、音频时间轴和字幕互相关联。修订后继续使用旧产物容易内容错配，所以 Agent 依赖规则要求重做相关衍生媒体。

**问：CLIP 能准确理解所有中文吗？**  
答：不能。本项目使用英文编码器和显式中文主题词典，未映射的复杂概念有局限。模型未就绪时降级为标签文本检索，并明确标识。

**问：本地运行是否代表所有数据都不联网？**  
答：不代表。应用、配置和文件保存在本机；真实模型调用与 Edge TTS 会向对应在线服务发送必要的输入。密钥不进入前端代码和作品 ZIP。

**问：你的个人贡献是什么？**  
答：据实说明本人需求选择、实际操作、核验、修改和评价。主要代码由 AI 协助生成的部分直接承认；真实API案例已完成；Trae独立页面的实际创建与后续Codex修复分别说明；对未完成的本人录屏或答辩不作完成声明。

**问：现场接口或网络失败怎么办？**  
答：展示可复核的已有真实产物与日志，说明现场失败原因和时间；可以切换到清楚标记的本地体验说明应用结构，但不能把它当作刚刚成功的真实 API 结果。
